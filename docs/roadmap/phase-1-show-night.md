# Phase 1: Show-night reliability and device setup

**Goal:** the show runs unattended all evening. Setting up projector output, audio and trigger
devices takes minutes and needs no SSH. Sound and light can be adjusted fast from the phone.

## 1.1 Real-hardware bring-up (do first)

- [ ] Run `scripts/deploy.sh --install` on the mini PC. Fix whatever breaks. Record each fix in
  `docs/operations.md` troubleshooting.
- [ ] **SPIKE** DRM: which connector and mode mpv picks, and if DRM master conflicts with getty.
- [ ] **SPIKE** ALSA: device names from `aplay -L` vs mpv `audio-device-list`; HDMI vs analog.
- [ ] **SPIKE** WLED `/json/cfg` key for WiFi sleep on the installed firmware. Fix `recommend.py` if it differs.
- [ ] `scripts/hubcheck.sh`: prints mpv version, `vainfo` summary, DRM connectors
  (`/sys/class/drm/card*-*/status`), `aplay -l`, free disk, time sync status. Used for bug reports.
- **Accept:** e2e show (trigger → video + 3 boards in sync) runs on real hardware for 1 h without errors in journal.

## 1.2 Device setup page (`/setup`)

New page, step list with a status dot per step. Works on phone.

| Step | Backend | UI |
|---|---|---|
| Projector output | List DRM connectors + modes from sysfs. Persist `mpv_drm_connector`, `mpv_drm_mode` in `RuntimeSettings`; applying restarts mpv. | Connector dropdown (connected first), mode dropdown, "Show test pattern on this output" |
| Audio output | Read mpv `audio-device-list` via IPC. Set `audio-device` live, persist `mpv_audio_device`. | Device dropdown with friendly names, "Play test sound", volume slider |
| Boards | Summary from `BoardManager`; run all recommendation checks at once. | Count online/adopted, "Check all settings", link to Boards |
| Trigger devices | Last trigger time + source per token. New WS type `trigger_seen`. | Token, prefilled curl and ESPHome snippet with hub URL + token, "waiting for trigger…" live light, test button |

- [ ] Backend: `player/devices.py` (pure parsing of sysfs + mpv device list, unit-tested), routes in `api/routes_setup.py`.
- [ ] mpv args from settings: `--drm-connector`, `--drm-mode`, `--audio-device`. Config file values stay the fallback.
- [ ] Test sound: generated once with ffmpeg (short "boo" chirp + sine sweep), cached in data dir, like the test pattern.
- [ ] Setup actions refuse while a show is playing (HTTP 409 with clear message).
- **Accept:** fresh hub, no SSH: pick output, pick audio, hear test sound, see trigger arrive.

## 1.3 Pre-show checklist (preflight)

- [ ] `show/preflight.py`: list of checks, each `{id, label, status ok|warn|fail, detail, fix?}`.
  Checks: boards adopted + online, RTT < 100 ms, WiFi sleep off, mpv alive + output set, audio
  device present, active profile media exists + codec OK, disk free > 2 GB, clock synced, mpv
  restarts last hour, trigger seen in last 30 min (warn only, idle_trigger profiles).
- [ ] `GET /api/preflight` runs all checks; WS `preflight` pushes changes every 10 s while page open.
- [ ] "Test everything": all boards flash 2 s, test sound, pattern 2 s, then restore idle.
- [ ] Dashboard banner when any check is `fail`.
- **Accept:** pulling a board's power turns its check red within 10 s and the banner appears.

## 1.4 Sync calibration

- [ ] Calibration clip generated by ffmpeg: black, white flash + beep every 2 s, 20 s loop.
- [ ] Engine "calibrate" mode: loops clip, boards flash white at the flash times via internal cues.
- [ ] Global offset slider applies live. New `Board.offset_ms` (migration) for per-board fine tune,
  added to latency compensation in the scheduler.
- [ ] Page section in `/setup`: "Watch projector and LEDs. Move slider until flashes match."
- **Accept:** offset change visible on next flash; per-board offset covered by a scheduler test.

## 1.5 Show mode (lock)

- [ ] `RuntimeSettings.show_lock`. When on, editing endpoints (profiles, cues, boards, media,
  settings except lock) return 423. Show controls stay open. Unlock needs the PIN when one is set.
- [ ] `/show` route: full-screen big buttons. Trigger, Play/Stop, Next, Blackout, brightness, volume,
  current profile + progress, preflight dot. Dashboard links to it.
- **Accept:** with lock on, a cue edit fails with 423 and the UI shows "Show mode on".

## 1.6 Quick sound and light helper

- [ ] Master volume: `RuntimeSettings.master_volume`, applied via mpv `volume` property on change and on each load.
- [ ] Audio delay (`audio-delay`) setting for speakers with latency.
- [ ] Brightness and volume caps (max values) so guests can't blast the street.
- [ ] Quick panel on Dashboard and `/show`: per-board brightness nudge and "base/off/white" buttons as manual overrides.
- **Accept:** volume change is audible within 200 ms and survives an mpv restart.

## 1.7 Persistent run log and stats

- [ ] `EventLog` table (ts, level, kind, message, data). Bus `event()` writes through, batched. 7-day retention.
- [ ] `GET /api/events?since=&kind=`. Dashboard "History" tab: list + triggers per hour, scare count tonight.
- **Accept:** events survive restart; count of triggers matches log.

## 1.8 Failure fallbacks and watchdog

- [ ] mpv stall detection: `time-pos` frozen > 2 s while playing ⇒ restart mpv, resume at last position (once), then fall back to idle.
- [ ] systemd watchdog: `WatchdogSec=30`, notify from the event loop (`sd_notify` via socket, no new dep).
- [ ] Board-local fallback: "Save fallback to boards" button writes the active base state as a WLED
  preset (slot 250) and sets it as boot preset. Manual only, since it writes flash.
- **Accept:** killing mpv mid-show resumes playback; a power-cycled board boots into the fallback look even with the hub down.

## Risks

- DRM output switching needs an mpv restart; screen goes black for ~1 s. Acceptable in setup only.
- Two ALSA openers fail on `hw:` devices. Phase 1 keeps one mpv; phase 4 handles mixing.
